Work that has been done

So far I have finished the serial implementation of the my quantum computer simulator. Overall this went rather smoothly with me creating a giant vector of complex numbers and manipulating them one at a time. I choose to utilize an input format of a JSON, so that we could effectively create small test cases. Although this did force me to utilize an external C++ dependency to parse the JSON.

Another thing I spent a lot of time working on was supporting Python scripts for the project. First, I created a Python script that would run my C++ implementation against the Qiskit benchmark and test it for correctness along with doing timing analysis. One mis-step I took was trying to create my own implementation of a Shors algorithm circuit. I sunk a good bit of time into this pursuit but it ended up not working out and I wanted to focus more on the parallel computation than this circuit generation aspect, so instead I am using MQT which is a database of quantum circuit premade for me to use.

Finally, I started the CUDA implementation of the code. While I think the implementation is quite close to being ready there are still a couple of bugs that I am tracking down as we are failing my correctness suite.

Schedule Status

I think that I am slightly behind schedule. I think that this is for two reasons, the first being the mistep of trying to create my own shors algorithm gate generator. The second is that I have been traveling over the last week, so I have had a lot less time to work than I would have liked. I still think I will be able to hit all of the goals I had laid out but might not be able to hit the nice to have. Here is my updated list of goals:

  1. Sequential baseline. Create a correct C++ state-vector simulator supporting H, T , and CNOT, together with reproducible benchmark circuits. Validate complex amplitudes against Qiskit on small circuits.
  2. GPU implementation. Implement CUDA kernels for parallel amplitude updates and measure their speedup relative to the sequential implementation on identical circuits and precision.
  3. Scheduling and optimization. Explore gate/kernel fusion and parallel evaluation of independent qubit groups where the circuit permits it. Evaluate how circuit structure and target-qubit positions affect performance.
  4. Application demonstration. If feasible, use the simulator for a small Shor factoring demonstration, targeting a number such as 119. This requires a suitable arithmetic circuit and decomposition of its gates; intermediate measurement and reset may be needed depending on the construction.

My performance target is 100–250 over my single-threaded CPU baseline on sufficiently large workloads. While there are a large number of independent amplitude updates, I worry that memory bandwidth and launch overhead may prevent me from reaching this goal. I also hope that with this speedup I am able to simulate larger quantum circuits that were unfeasible just on the CPU.

To evaluate speedup I will mainly be using the shors algorithm circuits while varying the number I want to factor. This should give me a good variety of circuits with different numbers of gates and different numbers of q-bits.

Plan for poster session

I plan to have graphs of speedup on my poster board and people are welcome to run the code and see it very slowly factorize numbers.

Current results

The only current results are the correctness of the sequential implementation. Currently I am able to factor 15 in around 4 minutes, but this is quite optimized.

Current Concerns

I have no concerns right now as I think it will just be about getting the rest of the code debugged and optimized.
